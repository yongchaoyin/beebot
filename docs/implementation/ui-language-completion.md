# 中文与英文界面补齐

2026-09-26。用户选择中文后，设置的导航、标题、主题、时区、本机执行和自动审核
仍大量显示英文。此前只有部分 BeeBot 新增页面读取了语言偏好，固定版原 UI
常量没有翻译，也没有在语言改变后更新编译缓存。

## 实际实现

- 在真实打包链的品牌适配之后运行 UI 语言 adapter，覆盖固定版 React chunks，
  而非只修改可编辑 `frontend/`。每个修改后的 chunk 继续记录前后摘要，
  严格 package/verify 会重建整套适配并逐字节比对。
- 精确词典对应代码拥有的 UI 常量和模板。AST 只处理显示属性、可证明的显示
  常量引用，以及经过固定函数摘要核对的 UI formatter。不会遍历 DOM 替换文字，
  不翻译用户聊天、Bot/群名称、规则、模型 ID、地址、密钥或协议值。
- 模板仅翻译外框，动态内容按原顺序插入；同名于“General”等词典项的用户文字
  保留原样。显示和操作共用局部变量时，只在显示读取点翻译，变量原值不变。
- 模块级导航和选项的标签按读取时语言计算；组件渲染属性保持普通值快照，
  防止 React 旧属性 getter 跟着改变而吞掉 DOM 更新。
- 编译缓存增加一个末尾语言槽。原有索引不变，React 的 cache clone 会携带该槽；
  仅语言变化时失效缓存，不在普通重渲染时清缓存，不使用 language key 重挂组件。
- 启动时统一加载已保存语言并广播到现有控件。保存成功才更新显示，保存失败
  在语言行内显示提示；迟到的初始读取不能覆盖新选择。创建、账户菜单和群列表
  复用该状态。此实现不宣称新增了跨设备语言同步。
- 原生菜单显式使用应用语言，同时保留 Electron 编辑角色、平台快捷键和原有
  开发者工具权限。可编辑设置源码使用 React 语言上下文，覆盖导航、通用、路由、
  自动审核、更新与电脑管理，保留用户草稿及既有确认状态。

语言是界面偏好，不改变 Bot 的回复语言、角色、模型、执行权限或工作状态。
供应商品牌、技术标识和上游返回的原始错误详情保留原文，界面说明单独翻译。

## 回归与边界

独立测试使用真实 React / compiler-runtime 和 Happy DOM；时间、bridge、账号和
持久化返回值为受控数据。覆盖普通重渲染、英→中→英→中、缓存克隆、静态选项、
placeholder/aria、单 Bot 与群聊草稿节点/焦点/选区/输入法组合、保存失败和读取
竞态，以及比较式、catch/for/switch 作用域不改变用户/协议值。用真实上游输入
执行完整适配，并核对输出中确实包含对应翻译。

审查实际修复了三类问题：React 旧 props getter 随语言改变造成 DOM 漏更新；
共享局部变量的赋值翻译会波及非显示用途；比较条件和变量遮蔽不能按文案处理。
这些边界均有专门回归，未通过放宽断言解决。

固定 formatter 9、聊天记录标签 1、提及行 6、路由用量 2、本机状态 4，均通过。
