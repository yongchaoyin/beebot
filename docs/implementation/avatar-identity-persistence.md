# 启动和重连时保持 Bot 头像身份

用户反馈同一位 Bot 在启动恢复缓存时显示另一种颜色和形状，连接恢复后才
回到已选外观。原因是实际打包 renderer 的 `roster.last-roster` schema 2
序列化函数 `Y0t` 漏存了 `avatarShape` 和 `avatarColor`。恢复后的行没有这些
字段，头像组件便按 Bot ID 生成默认外观；实时目录带回配置后又重新绘制。

修复只补齐该缓存白名单中的两个身份字段。保留 schema 2、原来的账户作用域、
实时快照优先级和清理行为；不按名字、列表位置或工作状态指定颜色。用户明确
修改颜色/形状、清空选项或恢复默认时，新值仍具有权威性。断线不会修改头像
身份，也不会把缓存提升为在线或工作完成。

照片继续使用原来的 `roster.agent-avatars` 缓存，按 Bot ID 和 avatarVersion
匹配，未把图片正文塞进目录缓存。群头像使用各成员身份，单 Bot 列表、标题
和消息头像仍共享同一套显示组件。动画只改变动作和表情。

旧缓存中已经丢失的字段不能凭空还原，需一次正常连接取得已保存配置；新缓存
随后在下次启动和离线恢复时保留它们。未修改用户的 Bot 配置或清空聊天记录。

改动位于固定上游 renderer 的受检适配器。上游函数摘要、替换锚点、归档重建、
签名和发布检查继续生效；没有直接修改生成的上游文件。
