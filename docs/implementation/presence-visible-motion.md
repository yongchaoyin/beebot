# 更容易看见的同事表情

2026-10-04。用户反馈最新官方 Grok Bot 的表情明显更频繁，而 BeeBot 看起来几乎不动。
本阶段调整 BeeBot 自有控制器的可见幅度、有限片段和轮换频率，不复制官方的
动画代码、关键帧或素材，不新增依赖、模型请求或状态推断。

## 原因和行为

实际打包列表已经通过 `isStatic: false` 使用共享 Presence 控制器，Natural
也是未保存动作偏好时的默认值。主要问题是表现参数过于保守：整个可见列表
只分到一个约 1.12 秒的片段，接着休息 3–6 秒；四分之一的机会仅眨眼。
十个可见身份逐个轮换时，单个同事需要等待数十秒。旧身体位移为 0.6 个
64 单位画布像素，在 28px 列表头像里只有约 0.26 个屏幕像素。
两个工作身份还会停止全部空闲轮换。

- Natural 继续每次只轮换一个空闲列表身份，片段延长为 1.72 秒，结束后
  休息 1.4–2.8 秒。四种片段都包含表情变化和身体姿态，眨眼可以随片段
  出现，但不再单独消耗一次机会。每个身体姿态在 28px 下至少有约 1px
  位移，随后完整回正。
- 七种工作动作增加了可辨识的身体和脸部变化；工作间歇改为 2.1–3.6 秒，
  回复间歇为 1.3–2.3 秒，间歇之前仍先完成有限片段和回正。
- 文档级自然动态预算改为四个身份，真实工作优先。空闲列表只借一个空位；
  四个工作身份占满时立即撤销空闲片段。同身份的主头像和镜像仍只占一位。
- Subtle 和低功耗条件仍只保留一位工作的眨眼；Off、系统减少动态、失焦、
  隐藏、离屏、历史头像、群拼图、小图标和自定义照片保持原边界。
  恢复后等待新周期，不补播已经过期的动作。

控制器仍只有一个文档级 observer、timeout 和暂时的 rAF。保持表情及片段
间歇不需要逐帧刷新；每个 WAAPI 动画只有一次播放。展示不会改写工作状态、
Bot 身份、任务、对话或用户偏好。

## 验证边界

使用 Node 26.5.0 和锁定依赖运行头像、表达式、工作编舞、侧栏回归，首轮
94/94 通过，零失败、零跳过。回归使用真实 SVG、React、控制器和 FIFO
提交队列；浏览器时钟、焦点、可见性和 WAAPI 完成事件是受控替身。
新增断言覆盖 28px 位移阈值、单身份一分钟至少 13 次有限片段、十身份
45 秒内轮换、四位工作者优先及一个共享时钟。既有单 Bot 和 Group 的
第二、第三条草稿、焦点、选区和排队发送检查通过。

另加回归运行 `presenceSharedModule()` 编译的实际打包入口，验证新频率和
四身份预算；随后侧栏及固定版 renderer/ASAR 校验 20/20 通过，零跳过，
包括按当前适配器重建实际固定入口、解析 JS 和校验归档的产物字节。
这些结果不是生产模型聊天、原生 Electron 动画帧率、耗电量或已安装版本
的实测结论。完整包验证由父阶段集中执行并记录。

## 隔离的原生 Electron 动效采样

`scripts/verify-native-avatar-motion.mjs` 使用 Node 26.5.0 和锁定 Electron
42.1.0，在独立临时 profile 中运行真实 SVG、WAAPI、rAF 和共享控制器。
启动前从 `dist/BeeBot.app` 的 ASAR 提取 Presence 模块与样式，核对模块与
当前 `presenceSharedModule()` 字节一致后冻结副本；采样期间不再读取可被
并行打包替换的应用。13/13 检查通过，零失败、零跳过，renderer 无错误。

- 四个真实 28px 空闲头像在 9.52 秒内采集 1020 帧；最大身体位移约
  1.142 个 CSS 屏幕像素，两个有限片段完成，最多一个空闲身份运动。
- 四个受控工作身份在 5.95 秒内采集 716 帧；四个身份均有原生身体与
  表情变化，最多同时四个身份运动，五个身体片段完成。同身份空闲镜像
  和额外空闲头像保持静止。
- 原生完成事件之后采到身体、脸部和动画均回正的静止帧。切换 Off 与
  销毁后，六个头像均无残留动画、位移或临时表情。

报告、逐帧坐标、原生动画事件及静止/运动 PNG 保存在未纳入版本控制的
`.build/avatar-motion-verification/`。此验证提供了实际小尺寸动效与有限
播放的原生证据；焦点和可见性由 fixture 明确提供，工作状态也是受控输入。
测试未调用模型、用户 Bot 或生产 profile，帧数不用于宣称生产帧率、
实际聊天表现或耗电量。
