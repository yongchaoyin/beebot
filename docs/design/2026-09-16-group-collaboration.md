# Group 讨论稿：已被正式规格替代

状态：历史讨论入口，2026-09-16 更新。

请以 [BeeBot 蜂群产品设计与开发规格](../BEEBOT_SWARM_DESIGN_AND_DEVELOPMENT.md) 为开发依据，尤其是第 3、5、6、11 节。旧草案的产品行为已整合到该文档，状态枚举、API 和执行约束统一由主规格维护。

最终确认的方向：

- 用户是 Boss，Bot 是有专长、记忆和专属电脑的长期同事；群提供共同上下文。
- 普通发言、单人/多人点名和 @所有人均可使用，不强制设立群主管。
- 单独 @某人只定向处理；明确“这次由你牵头”才指定本次工作的可选协调者。
- Bot 自主提出工作、认领、定向协商、交接和交付；每项执行有唯一责任人，用户无需逐项派工。
- 服务端的权威状态与执行约束不等于额外运行一个主管模型。
- 产品只提供 Web 界面，每个 Bot 的文件和账号默认私有；成果按版本显式分享。

开发者不得沿用旧稿中的简化状态机、桌面双端验收或共享电脑假设。官方资料和现有代码仅作事实参考，不覆盖用户确认的产品边界。
