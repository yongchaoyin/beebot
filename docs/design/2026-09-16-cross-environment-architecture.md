# 跨环境架构讨论稿：已被正式规格替代

状态：历史讨论入口，2026-09-17 更新。

请以 [BeeBot 蜂群产品设计与开发规格](../BEEBOT_SWARM_DESIGN_AND_DEVELOPMENT.md) 为开发依据，尤其是第 4、7、8、10 节。旧草案的完整实施内容已整合并修订到该文档；本页不再维护另一套接口或开发路线。

按最新需求修订的方向：

- 只有 Web 客户端，不开发或交付新的桌面客户端。
- 同一仓库构建 server/node/bot 镜像，覆盖 Windows / macOS / Linux；服务包与节点包独立部署，通过网络连接。同机组合只是安装选项。
- 每个 Bot 的执行器、私有记忆、模型会话与专属电脑在执行端运行；服务维护群公共状态，不集中运行所有 Bot 的模型循环。
- 独立远端与多节点群协作属于第一完整版本，不能推迟为后续混合模式。
- 每个 Bot 拥有独立且持久的文件、浏览器登录和虚拟桌面，通过明确的成果交接协作。
- Web 内真实观看、接管、归还 Bot 电脑属于第一完整版本。
- Web 界面的布局、主题、排版、组件状态、响应式与视觉验收见主规格第 3 节。

早期的 Web + 桌面双端、默认共享文件/账号、把电脑观看与接管留到后期，以及将完整 Bot 集中进服务侧公共 Worker 的方向已经取消，不可据此实施。

具体交付结构与三平台验收见 [服务与 Bot 独立部署设计](../DOCKER_DEPLOYMENT_DESIGN.md)。
